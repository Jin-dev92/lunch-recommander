# 위치 권한 재요청 및 검색 반경 확장 설계

## 배경

지도는 화면 진입 시 브라우저의 현재 위치를 한 번 요청한다. 요청이 실패하면
`현재 위치 권한이 필요합니다.`라는 경고만 표시되어 사용자가 화면에서 다시 시도할 수 없다.
검색 반경도 500m와 1km만 제공하므로 가까운 도보권만 찾고 싶은 사용자의 선택 폭이 좁다.

## 목표

- 위치 권한 경고를 통해 현재 위치 요청을 다시 시도할 수 있게 한다.
- 브라우저가 위치 권한을 차단한 상태라면 브라우저 설정에서 권한을 허용하도록 안내한다.
- 검색 반경에 100m와 300m를 추가해 100m, 300m, 500m, 1km를 제공한다.
- 프론트엔드 타입과 백엔드 입력 검증이 동일한 반경 값만 허용하게 한다.

## 범위

### 포함

- `Map` 컴포넌트의 위치 요청 재시도 동작과 접근 가능한 경고 버튼
- 위치 권한 실패 상태에 따른 사용자 안내
- 검색 반경 UI, 공유 타입, `nearby` Edge Function 검증 확장
- 위치 재요청과 네 가지 반경을 검증하는 프론트엔드·Edge Function 테스트
- README 주요 기능의 검색 반경 설명 갱신

### 제외

- 브라우저 설정 화면을 직접 여는 기능
- 위치를 입력하거나 주소로 검색하는 대체 흐름
- 지도 확대 수준을 검색 반경에 맞춰 자동 변경하는 기능
- 추천 가중치, 캐시 구조, rate limit 정책 변경

브라우저 보안 정책상 웹 애플리케이션은 사용자가 저장한 `denied` 권한을 직접 해제하거나
권한 창을 강제로 열 수 없다. 따라서 차단 상태에서는 설정 변경 방법을 문구로 안내한다.

## 사용자 흐름

1. 화면 진입 시 기존과 같이 고정밀 현재 위치 요청을 자동 실행한다.
2. 위치 요청이 성공하면 좌표를 저장하고 오류를 지운 뒤 지도를 초기화한다.
3. 위치 요청이 실패하면 `현재 위치 권한이 필요합니다.`를 클릭 가능한 경고 버튼으로 표시한다.
4. 사용자가 경고 버튼을 누르면 현재 위치 요청을 다시 실행한다.
5. 재요청이 성공하면 경고를 제거하고 정상 지도 흐름으로 복귀한다.
6. 재요청이 실패하거나 Permissions API에서 위치 권한이 `denied`로 확인되면
   `브라우저 설정에서 위치 권한을 허용해 주세요.`를 표시한다.
7. 사용자는 검색 반경에서 100m, 300m, 500m, 1km 중 하나를 선택할 수 있다.

## 컴포넌트와 데이터 흐름

### 위치 요청

`Map` 내부에 위치 요청 함수를 두고 최초 `useEffect`와 경고 버튼이 같은 함수를 호출한다.
함수는 기존 옵션인 `enableHighAccuracy: true`, `timeout: 10000`, `maximumAge: 0`을 유지한다.

오류 상태는 빈 문자열, 재시도 가능 안내, 브라우저 설정 안내 중 하나의 메시지로 관리한다.
성공 콜백은 이전 실패 메시지를 제거한 뒤 좌표를 저장한다. 재요청 중 중복 클릭을 막기 위해
요청 진행 상태에서는 버튼을 비활성화한다.

Permissions API는 지원되는 브라우저에서만 보조 신호로 사용한다. API가 없거나 조회가
실패해도 위치 요청 자체는 실행하며, 기능 실패로 처리하지 않는다. 실제 권한 요청은 반드시
사용자 클릭에서 `getCurrentPosition`을 호출해 브라우저가 프롬프트를 표시할 기회를 준다.

### 검색 반경

허용 반경은 다음 네 값이다.

```text
100 | 300 | 500 | 1000
```

- `Map` 선택 항목: 100m, 300m, 500m, 1km
- `SearchLocation.radius`: 네 값의 유니온 타입
- `nearby` Edge Function: 네 값만 허용하는 서버 측 검증

프론트엔드 검증만으로 제한하지 않고 Edge Function에서도 허용 목록을 유지한다. 이 변경은
기존 사용자 ID와 IP 기반 rate limit을 우회하지 않으며 Google Places API 호출 경로도
계속 Edge Function에 한정된다.

## 오류 처리

- 최초 위치 실패: 다시 시도할 수 있는 경고 버튼을 표시한다.
- 권한 차단 확인 또는 재시도 실패: 브라우저 설정 안내를 표시한다.
- Permissions API 미지원·조회 실패: 무시하고 Geolocation API 결과를 기준으로 처리한다.
- 위치 재요청 성공: 기존 오류를 제거한다.
- 잘못된 반경 요청: `nearby` Edge Function이 기존과 같이 HTTP 400을 반환한다.

## 접근성

- 경고는 의미 없는 클릭 가능한 문단 대신 실제 `button` 요소를 사용한다.
- 경고 영역의 `role="alert"`을 유지해 오류 메시지 변경을 보조 기술에 알린다.
- 버튼은 요청 진행 중 비활성화하며 시각적 포커스 표시를 제공한다.
- 브라우저 설정 안내도 사용자가 다시 시도할 수 있도록 버튼 형태를 유지한다.

## 테스트

### 프론트엔드

- 검색 반경 선택 항목 네 개가 표시된다.
- 최초 위치 실패 후 경고 버튼을 누르면 `getCurrentPosition`이 다시 호출된다.
- 재요청 성공 시 위치 콜백이 호출되고 경고가 사라진다.
- 권한이 차단된 경우 브라우저 설정 안내가 표시된다.
- 100m와 300m 선택 시 해당 반경이 위치 콜백에 전달된다.
- 기존 고정밀 옵션, 핀 이동, 지도 클릭, SDK 실패 테스트가 계속 통과한다.

### Edge Function

- 100m와 300m 요청이 입력 검증을 통과한다.
- 허용 목록에 없는 반경은 HTTP 400을 반환한다.
- 기존 인증, 사용자 ID와 IP 기반 rate limit, 캐시, 외부 API 오류 테스트가 계속 통과한다.

## 보안 검토

- 데이터베이스 테이블과 RLS 정책은 변경하지 않는다.
- 구독 상태와 사용량 데이터 구조를 변경하거나 민감 데이터와 혼재시키지 않는다.
- RBAC 및 인증 경로는 변경하지 않는다.
- Google Places API는 계속 `nearby` Edge Function에서만 호출하며 서버 키를 클라이언트에
  노출하지 않는다.
- 검색 반경이 추가되어도 사용자 ID와 IP 기반 이중 rate limit은 그대로 적용된다. 스팸
  요청은 Supabase 및 Google API 과금 증가로 이어질 수 있으므로 서버 제한을 유지한다.

## 성공 기준

- 위치 실패 경고를 클릭해 권한 요청을 다시 시도할 수 있다.
- 영구 차단 상태에서 브라우저 설정 안내를 볼 수 있다.
- 100m, 300m, 500m, 1km가 UI와 서버에서 일관되게 지원된다.
- 관련 자동화 테스트와 정적 검사가 통과한다.
