# 관리자 알림 채널 교체 설계 — Resend 이메일에서 Discord 웹훅으로

**작성일:** 2026-07-24
**대상:** `supabase/functions/_shared/`, `supabase/functions/signup-request/`
**선행 문서:** `docs/superpowers/specs/2026-07-23-signup-approval-design.md`

---

## 1. 문제

관리자 승인 기반 회원가입은 두 갈래의 알림을 보냅니다.

| 경로           | 대상               | 발송 수단                         |
| -------------- | ------------------ | --------------------------------- |
| 1. 관리자 알림 | 관리자 1명         | Resend API 직접 호출              |
| 2. 사용자 초대 | 승인된 가입 요청자 | Supabase Auth `inviteUserByEmail` |

경로 1이 배포 환경에서 동작하지 않습니다.

Resend는 **발신 도메인 인증**을 요구합니다. 도메인 인증이란 보내는 사람이 그 도메인의
소유자임을 증명하는 절차로, 도메인의 DNS에 SPF·DKIM 레코드를 추가해 수행합니다.
SPF와 DKIM은 각각 "이 도메인의 메일을 보낼 수 있는 서버 목록"과 "메일 본문에 붙는 서명"을
정의하는 표준으로, 수신 서버가 위조 메일을 걸러내는 데 씁니다.

인증을 마치기 전에는 발신 주소가 공용 주소인 `onboarding@resend.dev`로 고정되고,
**수신자도 Resend 계정 소유자 본인의 이메일로 제한**됩니다.

이 프로젝트는 Vercel 무료 배포의 `*.vercel.app` 주소를 사용합니다. 이 도메인은 Vercel의
소유이므로 DNS 레코드를 추가할 수 없고, 따라서 Resend 도메인 인증을 완료할 방법이 없습니다.

## 2. 대안 검토

경로 1의 성질을 보면 선택지가 좁혀집니다. **수신자가 고정된 1명이고, 전달할 내용은
승인 링크 하나뿐이며, 외부 사용자가 아니라 운영자가 봅니다.** 이메일이어야 할 이유가 없습니다.

| 대안                          | 도메인 필요 | 판단                                                                 |
| ----------------------------- | ----------- | -------------------------------------------------------------------- |
| Discord 웹훅                  | 불필요      | **채택.** 채널 웹훅 URL 하나로 끝나고 무료입니다.                    |
| Slack 웹훅                    | 불필요      | 동등한 대안입니다. 사용 중인 협업 도구에 따라 결정했습니다.          |
| Resend 유지 + 본인에게만 발송 | 불필요      | 관리자 이메일이 Resend 계정 이메일과 같아야만 동작하는 임시책입니다. |
| 도메인 구매 후 Resend 인증    | 필요        | 비용과 DNS 설정이 추가됩니다. 지금 필요한 수준을 넘습니다.           |

경로 2는 그대로 둡니다. Supabase Auth의 내장 발송은 Supabase 소유 도메인에서 나가므로
자체 도메인 없이도 임의 수신자에게 전달됩니다. 다만 무료 티어에는 시간당 발송 한도가 있어,
가입 요청이 늘면 Supabase Auth에 별도 SMTP를 설정해야 합니다.

## 3. 변경 내용

### 3.1 모듈 교체

`_shared/email.ts`를 `_shared/notify.ts`로 대체합니다. 더 이상 이메일을 보내지 않으므로
파일명이 하는 일과 어긋나지 않게 맞춥니다.

의존성 타입도 전송 수단에 맞게 바뀝니다.

```
이전: EmailDeps  { fetch, apiKey, from }      → https://api.resend.com/emails
이후: NotifyDeps { fetch, webhookUrl }        → 웹훅 URL로 직접 POST
```

`fetch`를 주입받는 구조는 유지합니다. 테스트에서 실제 네트워크를 타지 않고
요청 내용을 검증하기 위한 것으로, 교체와 무관하게 그대로 유효합니다.

### 3.2 죽은 값 제거

웹훅은 수신 대상이 URL 자체에 담겨 있어 관리자 이메일 주소가 필요 없습니다.
따라서 다음 세 가지를 걷어냅니다.

- `SignupRequestDeps.adminEmail`
- `sendAdmin(input)`의 `to` 필드
- Edge Function 시크릿 `ADMIN_EMAIL`

남겨두면 아무도 읽지 않는 환경변수를 계속 설정해야 하는 함정이 됩니다.

### 3.3 멘션 주입 차단

`signup-request` 엔드포인트는 브라우저를 거치지 않고 직접 호출할 수 있으므로,
`requesterEmail`에는 임의의 문자열이 들어올 수 있습니다.

이전 구현은 HTML 메일 본문에 값을 넣었기 때문에 태그 주입을 막는 HTML 이스케이프가
필요했습니다. Discord 메시지는 HTML이 아니므로 이 위험은 사라지지만, 대신 **멘션 주입**이
가능해집니다. 요청자 이메일에 `@everyone`을 넣으면 채널 전원에게 알림이 울립니다.

이를 막기 위해 요청 본문에 `allowed_mentions: { parse: [] }`를 넣습니다. 이 필드는
Discord가 메시지에서 어떤 멘션을 실제 알림으로 해석할지 지정하며, 빈 배열은
"어떤 멘션도 해석하지 않음"을 뜻합니다. 문자열은 그대로 보이되 알림은 발생하지 않습니다.

### 3.4 실패 처리

웹훅 성공 응답은 본문이 없는 `204 No Content`입니다. `response.ok`가 2xx 전체를 참으로
보므로 별도 분기 없이 그대로 사용합니다.

발송 실패 시 방금 저장한 pending 행을 되돌리는 기존 로직은 유지합니다. 이 롤백이 없으면
알림이 실패한 요청이 pending 상태로 남아, 재요청이 중복으로 차단되면서 관리자가 영영
알림을 받지 못하는 상태가 됩니다.

## 4. 운영 설정

코드 배포와 별개로 다음을 설정해야 합니다.

1. Discord 채널에서 **채널 편집 → 연동 → 웹훅 → 새 웹훅**으로 웹훅을 만들고 URL을 복사합니다.
2. Edge Function 시크릿에 `DISCORD_WEBHOOK_URL`을 등록합니다.
   ```
   supabase secrets set DISCORD_WEBHOOK_URL=<웹훅 URL>
   ```
3. 기존 `RESEND_API_KEY`, `RESEND_FROM`, `ADMIN_EMAIL` 시크릿은 더 이상 쓰이지 않으므로 제거합니다.

웹훅 URL은 그 자체로 게시 권한을 가지므로 비밀 값으로 취급합니다. 유출되면 누구나 해당
채널에 메시지를 보낼 수 있으니, 저장소나 프론트엔드 코드에 넣지 않습니다.

## 5. 검증

| 항목          | 명령                                                                           | 기준      |
| ------------- | ------------------------------------------------------------------------------ | --------- |
| Edge Function | `deno test --no-check --allow-env --node-modules-dir=auto supabase/functions/` | 전체 통과 |
| 프론트 테스트 | `npm test`                                                                     | 전체 통과 |
| 타입          | `npm run typecheck`                                                            | 오류 0    |

`notify.test.ts`는 세 가지를 확인합니다. 웹훅 URL로 승인 링크가 담긴 POST가 나가는지,
`allowed_mentions`가 멘션을 차단하도록 설정되는지, 2xx가 아닌 응답을 성공으로
처리하지 않는지입니다.

## 6. 남는 과제

- 사용자 초대 메일(경로 2)은 Supabase 내장 발송 한도에 묶여 있습니다. 가입이 늘면
  Supabase Auth에 SMTP를 설정해야 하며, 그 시점에는 도메인이 필요합니다.
- 알림 채널이 Discord 하나이므로 웹훅이 삭제되면 관리자가 요청을 인지할 수 없습니다.
  현재는 발송 실패 시 pending 행을 롤백해 요청자가 재시도할 수 있게 하는 것으로 대응합니다.
